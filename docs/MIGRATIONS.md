# دليل الهجرات (PF-01.4)

الهجرات = ملفات SQL في `database/migrations/` تُعدّل بنية قاعدة البيانات. المُشغِّل
`scripts/migrate.py` ينفّذ المعلَّق منها بالترتيب ويسجّله، ولا يعيد تنفيذ ما طُبِّق.
كل الأوامر من مجلد `backend`.

## الاستخدام اليومي
```
python ../scripts/migrate.py check             # فحص الملفات (آمن، بلا قاعدة بيانات)
python ../scripts/migrate.py status            # ما المطبَّق وما المعلَّق
python ../scripts/migrate.py apply --dry-run   # ماذا سينفَّذ (بدون تنفيذ)
python ../scripts/migrate.py apply             # التنفيذ (يطلب كتابة yes)
```
**خذ نسخة احتياطية قبل `apply` على القاعدة الحقيقية.**

## مرة واحدة لقاعدتك الحالية
ثلاث هجرات قديمة (002 و003 و005) لا تسجّل نفسها في `schema_migrations`، فستظهر
«معلَّقة» رغم أنها مطبَّقة فعلاً. سجّلها دون تشغيلها:
```
python ../scripts/migrate.py status
python ../scripts/migrate.py baseline --only 002,003,005
```
إن ظهرت في `status` هجرات معلَّقة **غير** هذه الثلاث فلا تسجّلها بـ baseline، بل
أخبرني قبل أي شيء.

## كتابة هجرة جديدة
1. رقم جديد فريد بعد آخر رقم، واسم بحروف إنجليزية صغيرة: `034_اسم_واضح.sql`.
2. اكتبها بحيث يمكن تشغيلها مرتين دون ضرر (`IF NOT EXISTS`, `ON CONFLICT DO NOTHING`).
3. لا تعدّل هجرة طُبِّقت. أي تصحيح = هجرة جديدة (المُشغِّل يكشف التعديل بالبصمة).
4. الأوامر المدمّرة (`DROP TABLE/COLUMN`، `TRUNCATE`، `DELETE FROM x;` بلا شرط) تُرفض
   في الفحص إلا بسطر صريح في الملف: `-- migrate: allow-destructive`.
5. شغّل `check` ثم `apply --dry-run`، ثم `apply`.

## الأرقام المكررة القديمة
022 و023 و024 فيها ملفان لكل رقم. لم تُعاد تسميتها لأن أسماءها مسجَّلة في قاعدتك.
تُنفَّذ بترتيب الاسم الأبجدي، وهو الترتيب الصحيح (مثلاً `022_..._account` قبل
`022_..._clearing`، فينشئ الأول حساب 217 كاملاً ويصير الثاني بلا أثر). تكرار جديد
يُرفض في الفحص.

## ضمانات التنفيذ
- ملف بلا `BEGIN/COMMIT` يُنفَّذ كله أو لا شيء. الفاشل يتراجع، ولا يُسجَّل، وما بعده لا يُنفَّذ.
- قفل على القاعدة يمنع تشغيل مُشغِّلين معاً.
- `status` يعرض «عُدِّلت!» لأي هجرة تغيّر محتواها بعد تطبيقها.

## فجوة معروفة: التركيب من الصفر
لا يمكن بناء قاعدة جديدة فارغة من `schema.sql` + الهجرات فقط، فالهجرة 002 تتطلب جداول
(`users`, `warehouses`, `warehouse_locations`, وأعمدة `id` في `items`) لا يُنشئها أي ملف SQL؛
أُنشئت يدوياً في قاعدتك. الحل الصحيح: لقطة لبنية القاعدة الحالية (schema-only) كهجرة
أساس `000`. هذا يحتاج قراءة بنية قاعدتك الفعلية، وهو من الخطوات التالية.
